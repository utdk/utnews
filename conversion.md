# Acceptance criteria

- [ ] Upon installation from this branch, visiting `/admin/config/workflow/workflows/manage/standard_workflow` shows the News node included as using the Standard Workflow, establishing that `Drupal\utnews_content_type_news\Hooks::addStandardWorkflow()` is working
- [ ] The `utnews` main module and the five sub-modules where conversion took place all have a `*.services.yml` declaration for `skip_procedural_hook_scan: true`
- [ ] After enabling `utnews_demo_content`, viewing an individual news article with sidebar fields, author information, main image, tags, categories, external link, and body summary shows those values rendering as expected, establishing that `Drupal\utnews_content_type_news\Hooks::preprocessNode()` and `Drupal\utnews_content_type_news\Hooks::theme()` are working
- [ ] After creating a Flex Page, the "News listing" blocks are not listed in the settings tray as reusable blocks (they **should** be available in "Create custom block", just not in the generic settings tray), demonstrating that `Drupal\utnews_block_type_news_listing\Hooks::pluginFilterBlockLayoutBuilderAlter()` is working
- [ ] After creating a Flex Page and placing an **inline** "News article listing" block on the page, the news listings render using `utnews_block_type_news_listing/templates/block--inline-block--utnews-article-listing.html.twig`, establishing that `Drupal\utnews_block_type_news_listing\Hooks::themeSuggestionsBlockAlter()` is working
- [ ] After creating a reusable "News listing" block (`/block/add/utnews_article_listing`) and placing it on a Flex page, the news listings render using `utnews_block_type_news_listing/templates/block--block-content--utnews-article-listing.html.twig`, establishing that `Drupal\utnews_block_type_news_listing\Hooks::theme()` is working
- [ ] When the same block is configured to "Display link back to main news page", a "View all News" button is rendered, establishing that `Drupal\utnews_block_type_news_listing\Hooks::preprocessBlock()` is working
- [ ] On the Views UI field picker for a node-based view, the "News Listing" field is available, establishing that `Drupal\utnews_block_type_news_listing\Hooks::viewsDataAlter()` is working
- [ ] Navigating to `/admin/structure/types/manage/utnews_news` shows the `The News add-on is read-only and may not be changed.` message, demonstrating that `Drupal\utnews_readonly\Hooks::formAlter()` is working
- [ ] Navigating to `/admin/structure/types/manage/utnews_news/fields` loads the `utnews_readonly/base` read-only styling, demonstrating that `Drupal\utnews_readonly\Hooks::pageAttachments()` is working
- [ ] Navigating to `/admin/structure/types` shows `View fields (read-only)` for the News content type, demonstrating that `Drupal\utnews_readonly\Hooks::entityOperationAlter()` is working
- [ ] Navigating to `/admin/structure/taxonomy/manage/utnews_authors/add` shows the author field labels as "Author bio" and "Author full name", establishing that `Drupal\utnews_vocabulary_authors\Hooks::formAlter()` is working
- [ ] Visiting `/admin/config/content/utnews` shows the listing page title configuration, establishing that `Drupal\utnews_view_listing_page\Hooks::formUtnewsGeneralConfigAlter()` is working
- [ ] Visiting `/news` shows expected border styling from `utexas_layout_builder_styles/border-styles`, establishing that `Drupal\utnews_view_listing_page\Hooks::viewsPreRender()` is working
- [ ] Visiting `/news` shows the sidebar at the expected width with the expected field border and background classes, establishing that `Drupal\utnews_view_listing_page\Hooks::preprocessPageNews()` is working
- [ ] After creating a Flex Page, the News facet and facet summary blocks are not listed in the settings tray, demonstrating that `Drupal\utnews_view_listing_page\Hooks::pluginFilterBlockLayoutBuilderAlter()` is working
- [ ] On the Views UI field picker for the `utnews` Search API index, the "News Listing (Search API)" field is available, establishing that `Drupal\utnews_view_listing_page\Hooks::viewsDataAlter()` is working
